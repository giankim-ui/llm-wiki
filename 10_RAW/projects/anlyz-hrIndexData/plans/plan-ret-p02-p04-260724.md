### 0-1. 조직 조인 키 교체 — 커버리지 17.4% → 97.3%

**증상**: 적격 퇴직자 2,699명 중 org_rank에 470명만 존재. 식품통합 MBU 2026-06은 실제 4명인데 조직 합계 0명.

**원인**: `build_retention.py:624`가 roster에 실재하는 `(부문,본부,팀)` 조합만 격자로 깔고 그 위에 퇴직자를 얹는다. 퇴직자 본부/팀은 퇴직자 원본 조직 텍스트를 그대로 복사한 값(`hq = hint["hq"] or "미상"`)이라 roster 체계와 안 맞아 얹힐 칸이 없다. 부문(BU) 판정은 정상이므로 전사·사업단위 뷰는 멀쩡하다 — 깨지는 건 본부/팀 층위뿐.

**조치**: 3중키 → **부서명 단일키**. 퇴직자 `조직명`(없으면 `조직명(4th)` → `조직명(3rd-a)`) ↔ roster `부서명`으로 조인해 그 roster 행의 계층을 채택. 실측 매칭률 97.3%.

### 0-2. 조직 계층 4단 정의

| 표시 명칭 | roster 컬럼 |
| --- | --- |
| 사업단위 | `부문명` |
| 본부/센터 | `본부명` |
| 담당/지사 | `지사/실` |
| 팀 | `팀` |

`부서명`은 조인 키 전용, 화면 계층에서 제외. 자동 롤업 예: `아이엔_1파트` → `식품통합 MBU_판촉서비스사업팀`, `COO_녹즙생산파트` → `COO_도안녹즙공장`, `FNC_공군제3훈련비행단_웅비식당` → `FNC_부산3팀`.

### 0-3. roster 정규화 (신규 — 현재 없음)

현 빌더는 roster 값을 그대로 쓴다. 아래 정규화를 선행한다.

1. **행 제외**: 법인명 ∈ {재단법인 한마음재단, 재단법인 풀무원재단, (주)피씨아이} · 직급 ∈ {`사외이사.`, `자문역[상근]`, `자문역[비상근]`, `상근고문`}
2. **사업단위 공란 보정** (연 130~184명이 통째로 누락 중): 본부명 `풀무원_온라인사업본부` → 식품통합 MBU / 지사·실 `풀무원_B2E사업부`·`풀무원_리빙케어사업부` → 신성장 SBU / 지사·실 `풀무원_이사회사무국` → CO
3. **본부/센터 공란 보정** (연 1,100~1,338명, 전체 ~20%): 지사·실 값 사용 → 그것도 공란이면 팀 값 → 전부 공란이면 `미상`
4. **BU alias**: `FDD SBU`·`NFB_FDD SBU` → 건강케어혁신 MBU (**전 기간**) / `풀무원_리빙케어사업부`·`로하스케어 SBU`·`HLS_로하스케어 SBU` → 신성장 SBU (**전 기간**) / `Japan SBU`·`HLS_푸메이뚜어러훠SBU` 제외
5. **미매칭 73건**: 사업단위까지만 집계하고 하위 계층은 **`그외조직`**으로 합산

> 4번의 전 기간 통합은 AGENTS.md의 "pre-move 이력 소급 금지" 원칙과 충돌한다. 추이 연속성을 위해 의도적으로 채택한 예외이므로 **AGENTS.md·retention skill을 함께 갱신**해 코드-계약 드리프트를 막을 것.

### 0-7. 직급 크로스워크 — 미매핑 21.1% → 1.4%

### 0-8. validation gate 추가

`--scratch` 빌드 후 아래를 검증한다. 하나라도 실패하면 promotion 금지.

1. 월×사업단위별 `sum(org_rank.leaver_count)` == `monthly.leaver_count`
2. `job`·`grade`·`tenure` 각각의 leaver 합계 == `monthly.leaver_count`
3. `reasons` leaver 합계 == `monthly.leaver_count`
4. 직급 모호·미매핑·제외 인원과 leaver 수를 별도 출력
5. 조직 분모 누락률을 validation.json에 기록
6. 집계 rate는 자식 rate 평균이 아니라 `sum(leaver)/sum(headcount)`로 재계산
7. 회귀값 `샘물 SBU` 2025-06 = `0.63%` 유지

- 사유별 색상은 고정. 월별 순위 변동에 따라 색을 바꾸지 않는다.
